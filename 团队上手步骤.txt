PantryPilot（食刻管家）· 团队上手：五个 Git 步骤 + 统一容器工作流
版本 1.1.2 / 2026-11-21
分支模型：main（受保护）+ dev/{psh,dyl,lym,lcy,lzy,zss}
--------------------------------------------------------------------------------
【一句话环境约定】
  后端基线是 Python 3.11+，而 Ubuntu 22.04 自带 3.10（jammy 只有 3.11.0rc1），
  所以 **Docker 容器是唯一受支持的后端运行环境**。宿主机 Python 版本不影响你干活。
  所有后端操作都通过 scripts/dev.sh 完成，命令完全一致，不存在"我这跑不起来"。
================================================================================

【第 0 步】一次性安装 Docker（只需一次）
--------------------------------------------------------------------------------
  sudo bash scripts/install_docker.sh
  newgrp docker          # 或注销后重新登录，让 docker 组权限生效
  docker version && docker compose version

【第 1 步】克隆并切到自己的分支
--------------------------------------------------------------------------------
  git clone https://github.com/537-tuzi/PantryPilot.git
  cd PantryPilot
  git fetch origin
  git switch dev/<你的名字>            # dyl / lym / lcy / lzy / zss
  git branch --set-upstream-to=origin/dev/<你的名字>
  git merge origin/main               # ← 取回工程骨架与最新修复

  如果提示 dev/<你的名字> 不存在（该分支只在远端），改用：
  git switch -c dev/<你的名字> --track origin/dev/<你的名字>
  git merge origin/main

【第 2 步】初始化环境（一条命令）
--------------------------------------------------------------------------------
  bash scripts/bootstrap.sh
  bash scripts/check_env.sh          # 自检，期望 FAIL 0

  bootstrap 会自动完成：写 .env 并生成随机 SECRET_KEY → 构建镜像 → 启动 db/backend/frontend
  → 迁移开发库 → 建测试库 → 授权维护账号 → 迁移测试库。

  前端热更新（可选，需要 Node 20+）：
  cd frontend && npm install && npm run dev      # http://localhost:5200，/api 自动代理

【第 3 步】认领目录，按《开发规范.md》第 3 节动手
--------------------------------------------------------------------------------
  A 组（前端/产品协调）  frontend/src/**
  B 组（后端/数据）      backend/app/{api,db,models,schemas,services,domain,repositories}/**
                         backend/alembic/**            <- 只有 B 组能写迁移
  C 组（AI/质量工程）    backend/app/ai/**  backend/tests/ai/**
                         deploy/**  scripts/**  .github/workflows/**
  共享文件（改动必须走 PR 且 CI 必绿）：
                         backend/app/main.py  backend/app/core/**
                         backend/requirements*.txt  frontend/package.json
                         frontend/vite.config.ts  deploy/docker-compose.yml  .env.example

  B1/B2 与 C1/C2 的具体人员由提交记录归属确定：谁先提交 backend/app/domain/ 与
  backend/app/ai/ 的首个有效提交，谁就在该组。确定后回填《10_工程管理台账.xlsx》。

【第 4 步】开发、提交、推送
--------------------------------------------------------------------------------
  每天开工前先同步 main：
    git fetch origin
    git merge origin/main

  写代码 -> 跑第 9 节自检清单 -> 提交：
    git add -A
    git commit -m "feat(inventory): add batch list endpoint"
    git push                # 推送到 origin/dev/<你的名字>

  提交信息格式：<type>(<scope>): <说明>
    type: feat fix docs style refactor perf test build ci chore
    scope: auth inventory expiry dashboard ai mealplan shopping deploy frontend backend
  禁止使用 “update”“fix bug”“修改” 这类无信息量的说明。

【第 5 步】发起 PR，评审后合入 main
--------------------------------------------------------------------------------
  GitHub -> Pull requests -> New pull request
    base: main
    compare: dev/<你的名字>

  PR 描述必须写清：改了什么、为什么、怎么验证。
  合入条件：CI 绿灯（后端检查 + 前端检查）。分支保护的审批人数为 0，作者可以自己批准并合并，
             但仍建议在 PR 里 @ 一名同伴看一遍；有人留下评论时，必须回复或解决后才能合并。

  合入后回到本地同步：
    git fetch origin
    git merge origin/main
    git push

统一工作流：所有后端操作都走 scripts/dev.sh
--------------------------------------------------------------------------------
  bash scripts/dev.sh up          # 构建镜像并启动 db/backend/frontend，迁移开发库
  bash scripts/dev.sh test        # 准备测试库（建库→授权→迁移）并在容器内跑 pytest
  bash scripts/dev.sh test-db     # 只准备测试库
  bash scripts/dev.sh migrate     # 对开发库执行 alembic upgrade head
  bash scripts/dev.sh seed        # 写入演示数据
  bash scripts/dev.sh ps / logs   # 状态 / 日志
  bash scripts/dev.sh backup      # 备份开发库到 backups/
  bash scripts/dev.sh restore <文件>
  bash scripts/dev.sh check       # 环境自检
  bash scripts/dev.sh shell       # 进入后端容器
  bash scripts/dev.sh openapi     # 打印接口地址（/docs、/openapi.json）

  常用地址：
  前端容器   http://localhost/          后端 http://localhost:8000
  前端热更新 http://localhost:5200      Swagger http://localhost/docs
================================================================================
日常节奏
  · 每天开工前 merge 一次 main；每天至少合入一次 PR，不要攒到最后一天
  · 一个 PR 只做一件事，控制在数百行以内
  · 破坏性操作、库存扣减、契约变更必须 Review
  · 禁止直接 push main；禁止 git push -f（rebase 后用 --force-with-lease）
  · 密钥只进服务端环境变量；.env、API Key、备份文件、个人草稿一律不提交
  · 测试库固定为 pantrypilot_test，测试夹具会强制校验；绝不能用开发库跑测试
